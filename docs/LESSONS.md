## Adding a lesson

Add one straight away, without asking, when you fix a defect, spot a bug while reading, the owner reports something broken, the owner corrects an assumption, or the owner makes a decision a later change could easily undo.

Put it under the nearest `##` section of the right file:

```markdown
### short-kebab-case-slug `bug`
The rule, stated as a pattern to check for. **Why:** the cause, if not obvious. **Applies to:** where it matters, if not obvious.
**Enforced by:** check <name> | test <script> | code <file> | none - <why it needs judgement>
```

- Tags: `bug` (found or fixed in code), `correction` (the owner corrected an assumption), `design` (a decision a later change must keep).
- Write the rule, not the story. No symptoms, no "tried A then B", no commit hashes.
- Slugs, never numbers. If a lesson already covers it, extend that one.
- Prefer enforcing: a code pattern becomes a check in `scripts/checks/repo-checks.mjs`, named in the `Enforced by` line.
- Run `npm run lessons` to rebuild the index below. `npm run check` fails on a bad slug, a bad tag, a repeated slug, a missing `Enforced by` line or a stale index.
