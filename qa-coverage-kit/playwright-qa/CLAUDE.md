## What this project is

A black-box Playwright + TypeScript E2E suite that drives a **live, deployed** instance of the app at `<qa.test_url>` (`workflow.toml`). It tests the app only from the outside: what's observable through the browser and network calls. The app's UI and data can drift independently of this suite.

## Identifiers — scoped, permanent, never renumbered

No identifier comes from a shared "next free number" sequence, so two people or agent runs on separate branches can never pick the same ID, and nothing ever needs renumbering.

| Item | Scheme | Example |
|---|---|---|
| Test | `<TICKET>-<n>`, numbered within the ticket that created it | `PROJ-327-1`, `PROJ-327-2` |
| Test from manual-test work (no ticket) | `MAN-<area-slug>-<n>` | `MAN-period-control-1` |
| Story (manual-test work only — ticket work links to the Jira story) | `MAN-<area-slug>` | `MAN-period-control` |
| Feature / workflow entry | `F-<slug>` / `WF-<slug>` | `F-order-totals` |
| Test-infrastructure issue | `ISS-TS-<slug>` in `scripts/KNOWN-ISSUES.md` | `ISS-TS-session-expiry` |
| App bug | The Jira key — app bugs are filed in Jira, not here | `PROJ-812` |

Rules:

1. **Never reuse or renumber an ID.** Removing a test retires its ID.
2. **Every test declaration starts with its ID**, and its docstring sits directly above it in this format:

   ```ts
   /** PROJ-327-1: Order total includes tax | PROJ-327 AC2 | Positive | High
    *  Verifies: the order detail page shows a total equal to subtotal plus tax for a taxable order. */
   test('PROJ-327-1 — order total includes tax', { tag: ['@PROJ-327'] }, async ({ page }) => {
   ```

   The first line is `<ID>: <title> | <ticket or story> AC<n> | <Type> | <Priority>`. Type is Positive, Negative, Boundary or Workflow; Priority is Critical, High, Medium or Low. The `Verifies:` line is one plain-language sentence saying what the test proves — it's what non-technical readers see in the generated index.
3. **Tag every ticket that creates or changes a test** (`{ tag: ['@PROJ-327', '@PROJ-412'] }`). The ID records the originating ticket; the tags record every ticket that touched it.
4. **Run `npm run qa:ledger -- --write` after any change to specs**, then `npm run qa:ledger -- --check`. The ledger checks IDs and docstrings and regenerates `qa-output/test-index.md`, `qa-output/jira-test-mapping.md`, and the `<!-- qa-ledger:… -->` blocks in this file and `README.md`. Never hand-edit a generated file or block.

**Where the documentation lives.** For automated tests, the spec (docstring + code, using readably named page-object methods) is the record, and `test-index.md` is the readable list generated from it. `qa-output/test-cases.md` holds prose only for cases with no automation (blocked on data, manual-only). Full step-by-step drafts exist during review, in the run's draft file, and aren't copied anywhere.

## Running tests

From `scripts/`:

- **Whole suite**: `npm test`, headless. `playwright.config.ts` has a `globalTimeout` — keep the suite inside it.
- **One spec / some IDs**: `npx playwright test tests/core/<area>/<file>.spec.ts --grep "PROJ-327-1|PROJ-327-2"`.
- **Auth caching**: `auth.setup.ts` signs in once and reuses the saved login only while it's younger than `AUTH_REUSE_MINUTES`. Set that to *session lifetime − longest run* so a reused login never expires mid-run.
- **Toolchain crash at config load**: see `QA-LESSONS.md` → `config-load-crash-is-a-toolchain-mismatch-not-a-suite-bug`.

## Key conventions

- **Page Object Model** in `scripts/pages/` — one class per page, locators as readonly properties, actions as methods. **Spec files hold no selectors.** Navigate with `BasePage.open(path, ready)`, which waits for a named element. Name methods for what the user does (`selectPeriod('Last 30 days')`), because the spec is the readable record of each test's steps.
- **Size coverage to risk; assert behaviour, not presence.** No fixed quota of cases per story. Prefer assertions on outcomes — values, URL state, counts, the result of an action — over "element is visible". See `QA-LESSONS.md` → `prefer-behaviour-assertions-size-coverage-to-risk`.
- **`test.fail()` at declaration** = the test asserts correct behaviour and is **expected to fail because of a known app bug**. Put the bug's Jira key in a comment **above** the docstring — nothing may sit between the docstring and `test.fail(`. The test turns red ("expected to fail but passed") when the bug is fixed, which is the signal to remove the marker. Never rewrite an assertion to accept buggy behaviour.
- **`test.skip()` at declaration** = a **permanent** skip for a test that cannot run (missing environment state, a removed flow) — not for a known bug. Record it in `README.md` → Permanently Skipped Tests and in `scripts/KNOWN-ISSUES.md`.
- **`test.skip()` inside a test body** = a runtime-conditional skip when a live precondition isn't met at that moment. Deliberate for a shared, mutable environment — don't turn it into an unconditional skip or pass.
- **Avoid `waitForLoadState('networkidle')`.** Apps with background polling or link prefetching may never go idle. Wait for a specific element or URL instead.
- **Records the suite creates** are named with a fixed prefix (e.g. `QA-auto …`) and swept by that prefix in `beforeAll` *and* `afterAll`. Never create a record without the prefix, and never widen a sweep beyond it.

## Environment setup

`scripts/.env` (gitignored) must define `BASE_URL`, `QA_EMAIL` and `QA_PASSWORD`; see `scripts/.env.example`.

**Playwright MCP** is defined in the repo-root `.mcp.json` (pinned `@playwright/mcp`, Chrome, headless, isolated profile loaded from `scripts/fixtures/auth.json`). The browser reads the saved login only when it launches: for a fresh one, run `npm run setup`, then `browser_close`, then navigate. Never read `scripts/.env` or `fixtures/auth.json`; `.claude/settings.json` and the `guard-secret-reads` hook deny both.
